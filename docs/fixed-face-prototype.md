# 正面・固定位置の顔はめ試作

2026-10-20。XRiftへアップロードしたv1から派生したローカル試作。XRiftの登録IDとv1は変更していない。

## 実装した範囲

- 通常の鏡像へ、検出した顔輪郭内の実写だけを透明CanvasTextureとして重ねる。
- 反射は純正`Mirror`を使用。顔テクスチャはこのアイテムの鏡面に配置し、アバター本体を変更しない。
- 正面・固定距離に限定。左右、上下、大きさ、ガイド表示、リセットをローカル画面とアイテムの3Dボタンから操作できる。
- カメラ位置がアイテムのローカル座標でX±0.20m、Z=1.60±0.25m、視線が鏡正面から約20度以内の場合だけ合成を表示する。立ち位置から外れたら顔が鏡面に残らないよう隠す。
- 全面カメラモードを残し、モード切替時は顔モデルと推論タイマーを解放する。
- 検出0件・2件以上の場合は顔の合成を隠す。停止・タブ非表示・削除時は元のアバターの反射に戻る。
- WASMとモデルは配布物へ同梱する構成。カメラ画像の送信・録画・保存はしない。

## 確認結果

- 型チェック、ビルド成功。
- XRiftコード検査: `23 files / APPROVE 23`。
- 従来の全面カメラモード: 模擬カメラによる既存8項目が成功。
- 顔はめ: 公開サンプル写真を動画入力へ置換し、実際のMediaPipeモデルで1顔検出・輪郭切り抜き・反射像との合成が成功。
- 大きさ調整とリセット、顔なしでの非表示、十分な大きさの2顔入力での非表示、停止と再開、削除時のカメラ終了が成功。
- ローカル画面でカメラと検証アバターを横へ0.5m動かし、非表示になることと、正面位置へ戻ると再表示することを確認。
- 開発プレビューでは外部リクエストなし。本番ビルドの独立プレビューは標準SDKがフォント定義JSONを外部取得したが、顔モデル・WASMはローカルから読み込み、カメラ画像を送信する処理はない。
- 本番ビルドでも同じ顔はめ検証が成功。実行環境で到達可能な`127.0.0.1:5280`を検証に使用。

## 証拠と再現

- `output/playwright/face-verification.json`: 開発プレビューの検証結果。
- `output/playwright/face-production-verification.json`: 本番ビルドの検証結果。
- `output/playwright/face-found.png`, `face-missing.png`: 顔を検出した画面と、見失った画面。人物は検証用の公開サンプルで、利用者本人ではない。
- `output/playwright/face-security.txt`: XRiftコード検査。
- `npm run assets:face -- --test-fixture`で素材を準備し、`npm run dev`と別ターミナルの`npm run verify:face`で再現。
- `TRUTH_MIRROR_BASE_URL`を設定すると`npm run preview`のURLでも検証可能。写真はテスト側のルーティングで供給し、アプリのビルドには含めない。

## 未確認・制限

ローカルの反射対象は簡易検証アバター。XRift内の本人のアバター、および本人の実カメラによる顔はめは未確認。
頭ボーンへの追従は行わず、固定した鏡面上の位置へ合成する。移動・首振り・しゃがみ・体型差には手動再調整が必要。
手や髪による顔の遮蔽、肌色・照明の一致、横顔や低性能PCでの品質は未検証。
モデルが顔を見落とす場合は複数人を確実に検出できない。人物の同一性を識別する機能ではない。
推論は最大約10Hzのメインスレッド処理。Worker化や負荷測定は次の改善対象。
