# 顔検知・鏡の中だけの顔はめ案

状態: 調査・提案。v1には未実装。2026-10-20時点。
利用者は最初の試作範囲として「鏡の中だけ、自分のアバターの顔が実写になる」を選択済み。

## 目指す体験

現状の「鏡の全面がWebカメラ映像」から、通常のアバターの鏡像を背景にして、
自分のアバターの顔の領域だけを実写に切り替える。
本人の鏡の中だけで表示する。鏡の外や他人への表示は今回の試作範囲に含めない。

## 成立しそうな部分

- MediaPipe Face Landmarkerはブラウザで顔のランドマーク、表情のブレンドシェイプ、顔姿勢の変換行列を取得できる。
- 顔輪郭の点でカメラ映像を切り抜き、背景を透明化した顔テクスチャを生成する構成が候補。
- 生成AIの顔交換ではなく、本人の映像を顔輪郭に沿って切り抜いて貼る方式なので、推論も描画もPC内で処理する設計にできる。
- モデル・WASMの初回読み込みと、カメラ画像の外部送信は区別する。素材を配信先に同梱する構成を調べる。

## XRift側の未確認点

公開APIの`useUsers`は自分の移動・視線方向・アバター高を提供するが、
調査した公開リファレンスと手元SDK 0.56.1では、本人のVRMインスタンスや頭ボーンを取得・差し替えするAPIを確認できなかった。
これはAPIが絶対に存在しないという意味ではなく、現時点で公式契約として確認できていないという意味。

純正`Mirror`は反射用で、顔領域のマスクや描画対象の差し替えのpropは公開されていない。
手元SDKではReflectorと三人称レイヤーでアバター全身を反射している。
頭ボーンへのアクセスなしで位置とアバター高だけから顔位置を推定すると、しゃがみ・首傾け・体型差でずれる。

## 段階案

1. **顔だけの切り抜き**: 現在の鏡に顔輪郭の切り抜き結果を表示する。顔検知なし・複数顔・見失い時の動作を確認する。
2. **固定位置での顔はめ**: 正面から覗く撮影ブースのように立ち位置を固定し、鏡像上の顔位置と実写の大きさを手動調整する。頭への追従が未実証であることを画面に明示する。
3. **自由に動ける顔はめ**: 自分の頭ボーンと鏡の反射カメラの対応を確認し、鏡専用の合成パスで顔を配置する。通常描画や他の鏡へ漏れないことも検証する。

頭ボーンの公式取得ができなければ、3は保留し、2の固定ブース版を独立した試作として評価する。
シーン探索で偶然見つけたメッシュ名を前提に、他のアバターやマテリアルを恒久的に書き換える構成は採用しない。

## 品質と停止条件

- 目・口・輪郭の対応、顔サイズ、鏡像の左右反転、頭の回転、手や髪による隠れを確認する。
- 顔を見失ったら実写合成を消す。複数の顔が映ったときに勝手に別人へ切り替えない。
- メインスレッドを止めないよう推論頻度・Worker化を評価する。公式Webガイドは動画検出が同期処理でUIスレッドをブロックしうると記載。
- タブ非表示・カメラ停止・アイテム削除時に、推論ループ、Worker、テクスチャ、カメラを終了する。
- 鏡の中だけへの合成と、アバター自体の顔変更は別々に検証する。
